# ADR-0006: OCR を回避する代替手段の調査

- **ステータス:** 採択（OCR 経路を維持する）
- **日付:** 2026-08-08
- **背景:** [ADR-0004](0004-page-acquisition.md) で「DOM に本文が無く OCR は必須」と結論したため、
  Cloud Reader 以外の経路が存在しないかを日英の公開情報で調査した

## 調査結果

### A. グリフ難読化の解除（英語書籍・Kindle Web）

Kindle Web Reader は書籍によって、本文を**グリフ ID の列**として配信する。

- 配信物は TAR で、`page_data_*.json`（グリフ ID 列）と `glyphs.json`（SVG パス定義）を含む
- 文字 `T` は Unicode 84 ではなく「グリフ 24」として表現される
- **グリフ ID のマッピングは約 5 ページごとにランダムに変わる**
- SVG パスには解析を妨害するダミーコマンドが混入されている
- 920 ページで 184 リクエスト、361 ユニークグリフ、総グリフ数 約 105 万

これを解読した公開研究が 2 件ある。SVG を 512x512 でレンダリングして
知覚ハッシュ＋SSIM で TTF フォント（Bookerly）と照合し、361/361 を
平均 SSIM 0.9527 で復元している。

**本プロジェクトには適用できない。** 理由:

1. **観測した書籍にはグリフ配信が存在しない。** [ADR-0004](0004-page-acquisition.md) の実測では
   `<canvas>` 0 件、DOM テキスト 0 文字、`glyphs.json` に相当するものも無く、
   **サーバ側でレンダリング済みのページ画像（`kg-full-page-img`）**が配信されていた
2. 公開研究はいずれも**英語書籍（Bookerly フォント、361 グリフ）**のみを対象としており、
   縦書き日本語や画像レンダリングへの言及が無い。日本語では常用漢字だけで数千字あり、
   照合の前提が成立しにくい
3. **改良版の実装は、復元したグリフを PNG に描画し直して Tesseract に通している。**
   つまり難読化を解いた先でも結局 OCR している。本プロジェクトの経路より劣る
4. グリフ難読化は明らかに抽出対策として実装されたものであり、これを解除することは
   本プロジェクトが README で明示している「DRM の技術的保護手段を回避する機能は含まない」
   という立場と衝突する

### B. アクセシビリティ API（Kindle for PC + Windows UI Automation）

デスクトップ版 Kindle は Narrator / NVDA / JAWS に対応しており、
対応書籍では本文が Windows UI Automation 経由で取得できる。
スクリーンリーダーが読み上げられる以上、テキストが API 上に露出しているはずである。
**これは公開された支援技術向け API であり、難読化の解除には当たらない。**

しかし日本語書籍には期待できない。

- **Amazon.co.jp の商品ページには「Screen Reader: Supported」の項目自体が存在しない**
  （Amazon.com には存在する）。日本で販売される Kindle 本はスクリーンリーダー非対応
- 日本で販売される Kindle 端末には読み上げ機能が搭載されていない
- 対応書籍であっても、**多くのタイトルはアクセシビリティのテキスト層を無効化しており**、
  さらに 5〜10% のコピー上限に達すると以降取得できなくなる、という報告がある

### C. コピー機能・ハイライトのエクスポート

Kindle は書籍あたり 5〜10% 程度のテキストコピーを許可するが、
上限に達すると以降ロックされる。ハイライトのエクスポートは
自分が引いた箇所しか出力されない。全文取得には使えない。

### D. DRM フリーで別途入手する

DRM フリーの EPUB / PDF を販売している日本語ストアが存在する。

| ストア | 分野 |
|---|---|
| 達人出版会 | IT 技術書（他社タイトルも取り扱い） |
| 技術評論社 | 技術書（購入後 PDF / EPUB をダウンロード） |
| オライリー・ジャパン | 技術書 |
| 翔泳社 SEshop / インプレス | 技術書 |

**これが唯一「完全に正確なテキストが得られる」手段である。**
ただし対象は技術書・実用書に限られ、ライトノベル・マンガの DRM フリー販売は見当たらない。
購入者のメールアドレスが透かしとして埋め込まれる場合がある点に注意。

### E. スクリーンショット + OCR

英語圏の調査記事は一致して、**「OCR だけが生き残っている全文取得手法」**と結論している。
Amazon が canvas 描画・フォント難読化・コピー上限を実装しても、
画面に表示される以上ピクセルは読める、という理屈である。

## 本調査で得られた新しい知見

公開されている英語の技術記事は、いずれも **canvas 描画 + グリフ難読化**を
Kindle Web の実装として報告している。しかし [ADR-0004](0004-page-acquisition.md) で実測した
日本語縦書き書籍は、**canvas ですらなくサーバ側レンダリング済みの画像**だった。

**Amazon は日本語縦書き書籍に対して、英語書籍とは別の、より抽出困難な
配信パイプラインを使っている可能性が高い。** この観測を報告している公開情報は
調査範囲では見つからなかった。

これは本プロジェクトにとって次の意味を持つ。

- 英語圏で有効とされる手法（グリフ復元）を輸入しても、対象書籍には効かない
- 一方で、画像配信であるがゆえに**ページ画像を原寸で直接取得できる**という
  [ADR-0004](0004-page-acquisition.md) の利点が成立している。難読化された
  グリフ列よりも、素直なページ画像の方が扱いやすい

## 決定

### 1. OCR 経路を維持する

日本語書籍について、OCR を回避する実用的な手段は存在しない。
[ADR-0004](0004-page-acquisition.md) / [ADR-0005](0005-reader-display-settings.md) の方針を変更しない。

### 2. グリフ難読化の解除は実装しない

技術的に適用できないうえ、本プロジェクトの「技術的保護手段を回避しない」という
立場と衝突する。将来 Amazon が日本語書籍もグリフ配信に切り替えたとしても、
この判断は維持する。

### 3. 技術書は DRM フリー版の有無を確認する導線を用意する

蔵書のうち技術書・実用書については、DRM フリー版を別途入手した方が
**OCR より正確で、後処理も校閲も不要**である。

`plan` フェーズで書籍を分類する際、技術書と判定されたものには
「DRM フリー版が存在する可能性がある」旨を出力する。
判定は出版社名によるヒューリスティックで足りる。

### 4. アクセシビリティ API は「安価な確認項目」として残す

デスクトップ版 Kindle は本環境に未インストールのため未検証。
公開情報からは日本語書籍で機能する見込みは薄いが、
**公開 API であり難読化の解除にも当たらない**ため、試す価値はある。

蔵書に洋書が含まれる場合は特に確認する価値がある
（Amazon.com の書籍はスクリーンリーダー対応が明示されている）。

## 副産物

`Xetera/kindle-api`（Node.js から Kindle の内部 API を叩く、ヘッドレスブラウザ不要）
というライブラリが存在する。**本文取得ではなく蔵書一覧の取得**に使える可能性があり、
`plan` フェーズ（蔵書ダンプ → books.json 生成）の実装候補として記録しておく。
